# Governance

The repository is maintained under the connected GitHub account that publishes it. Maintainers define release readiness and accept responsibility for merges, dependency updates, release notes and security response. Contributors participate through issues, reviews, tests and pull requests.

Technical decisions should be evidence-led: prioritize correct behavior, hardware-enforced isolation, measured performance, simple trusted computing bases, and reproducible tests. Major design changes should state the affected ABI, threat model, architecture support and rollback plan.

No code has automatic authority because it was accepted into the community repository. Releases remain pre-alpha until independent kernel gates, hardware testing and security reviews justify a changed label. Governance can be formalized further as contributors join; attribution and clear licensing will be preserved.
